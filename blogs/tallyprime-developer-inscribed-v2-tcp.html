TallyPrime Developer Release 7.2: Inscribed V2 TCP Explained

Developer
Oct 23, 2026
4 min read
Choose the right TCP format and verify compatibility before deployment

What is Inscribed V2?

TallyPrime Developer Release 7.2 introduces Inscribed V2, a new TCP format with an enhanced encryption mechanism for TDL customisations. The TCP Format section under Project Properties > Build Options makes it possible to choose the required compilation format when building a project.

Inscribed V2 is intended for developers who need the newer format for distributing their custom solutions. It is a build and compatibility decision: confirm the target TallyPrime version of every customer environment before choosing it.

TCP format options in Release 7.2

  • Regular: The regular TCP option remains available.
  • Inscribed V1: The previous Inscribed format is renamed Inscribed V1 in Release 7.2. The change is a name update and does not alter its functionality.
  • Inscribed V2: The newer format, with an enhanced encryption mechanism for TDL customisations.

Compatibility to check before building

Inscribed V2 TCPs can be loaded only in TallyPrime Release 7.2 and later. Regular and Inscribed V1 TCPs continue to be supported in Release 7.2 and later. If a solution must run on earlier TallyPrime releases, do not assume an Inscribed V2 build will load there; check the official compatibility guidance and build for the versions you support.

A careful build and rollout checklist

  1. Confirm the TallyPrime versions used by your intended customers.
  2. Open the project in a compatible TallyPrime Developer release and review Project Properties > Build Options.
  3. Select Regular, Inscribed V1 or Inscribed V2 based on compatibility and distribution requirements.
  4. Build and test the TCP in a clean environment running the target TallyPrime version.
  5. Document the selected format and minimum supported version for deployment.
  6. Keep source files and release records securely maintained for future updates and troubleshooting.

Why test before distribution?

A TCP that builds successfully is not automatically validated for every customer setup. Testing with the intended TallyPrime version helps identify loading or compatibility issues before rollout. For customisations used across multiple releases, keep a clear support matrix and distribute a build that matches the environment.

Conclusion

Inscribed V2 gives TDL developers a new TCP format in TallyPrime Developer Release 7.2, while the Regular and Inscribed V1 formats remain available. The key point is compatibility: V2 requires TallyPrime Release 7.2 or later. Review the official TallyPrime Developer Release 7.2 notes and the working with projects guide before adopting the format.
